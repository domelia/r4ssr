Введение в анализ текстов

Анализ текстов (Text Mining / NLP - Natural Language Processing — обработка естественного языка) — это совокупность методов, позволяющих извлекать информацию из неструктурированных текстовых данных: новостей, постов в социальных сетях, отзывов, комментариев, правовых, художественных и иных документов.

Примерный алгоритм анализа текстов включает несколько важных шагов:

  1. Сбор и создание корпуса — загрузка текстов и присвоение им метаданных.
  2. Предобработка — токенизация, приведение к нижнему регистру, удаление стоп-слов, стемминг / лемматизация.
  3. Представление текста — создание матрицы терминов документов (терм-документной матрицы)(DFM / DTM).
  4. Частотный анализ — анализ наиболее часто встречающихся слов, ключевых слов, создание «облака» слов.
  5. Тематическое моделирование — выявление скрытых тем в корпусе (LDA).
  6. Сентимент-анализ — определение тональности текстов (позитивная / негативная).

В этом тьюториале мы будем работать с корпусом из новостных русскоязычных текстов, охватывающих несколько тематических областей. Основной инструмент — пакет quanteda, а также пакет topicmodels, который мы будем использовать для проведения тематического анализа LDA. В конце тьюториала мы расширим наши представления об анализе, включив в него анализ векторных представлений на основе предобученных моделей-трансформеров.

Корпус текстов

Что такое корпус?

Корпус — это организованная коллекция текстов, часто сопровождаемая метаданными (о том, каковы источник, дата, тема, автор текста и другие атрибуты). В пакете quanteda корпус создается функцией corpus(). Каждый документ в корпусе может иметь произвольный набор переменных (docvars).

В данном тьюториале мы будем работать с текстами новостей, составляющих часть большого набора данных Lenta.ru, собранного Дмитрием Юткиным для задач NLP. Предобработка текстов

Токенизация и очистка

Токенизация — разбиение текста на отдельные единицы (токены), чаще всего слова. Функция tokens() в quanteda выполняет токенизацию и позволяет одновременно удалить знаки препинания, цифры и специальные символы.

Стоп-слова — служебные слова, не несущие смысловой нагрузки (предлоги, союзы, местоимения). Для русского языка они доступны через stopwords("ru").

Стемминг — приведение слов к основе (стемме). Например, «играет», «играл», «игры» → «игр». Это нестрогая нормализация; более точный метод — лемматизация (приведение к словарной форме), реализованная, например, в пакете udpipe.

Упражнение 4 — Токенизация

Работать с целым текстом довольно трудно, логично его разделить на более мелкие части, имеющие смысл, и попытаться эти части проанализировать. Процесс разбивки текста на отдельные признаки называется токенизация, и именно он позволяет нам обрабатывать тексты автоматически.

Признаками (Features) могут быть отдельные слова, цепочки слов, предложения, числа или знаки пунктуации.

Упражнение 6 — Лемматизация

Хотя стемминг – это довольно быстрый и простой инструмент приведения слов “к общему знаменателю”, он делает это довольно грубо, просто обрезая окончания, то есть на выходе мы видим основу слова.

Лемматизация – более тонкий путь, позволяющий использовать морфологические свойства слова. В результате лемматизации слово приводится к словарной форме. Для существительного это единственное число и именительный падеж, для прилагательного – форма мужского рода единственного числа, для глагола - неопределенная форма (инфинитив).

Проведем лемматизацию с помощью UDPipe – мультиязычного NLP‑инструмента, позволяющего сделать сразу несколько полезных действий:

  • токенизацию (разлеить текст на предложения и слова),
  • POS‑теггинг (определить части речи),
  • лемматизацию (привести к словарной форме слова),
  • синтаксический разбор (определить грамматическую структуру предложения: кто с кем и какие отношения связывают).

Тематическое моделирование

Что такое LDA?

Латентное размещение Дирихле (Latent Dirichlet Allocation, LDA) — вероятностная генеративная модель тематического моделирования, в которой каждый документ рассматривается как смесь нескольких латентных тем, а каждая тема — как распределение вероятностей по словам словаря. Для каждой темы \(k\) задается распределение по словам \(\varphi_k\), для каждого документа \(d\) — распределение по темам \(\theta_d\), а для каждого слова в документе скрыто, к какой теме оно относится (переменная \(z_{dn}\)).

Совместное распределение наблюдаемых слов \(w\) и скрытых переменных \((\theta, \varphi, z)\) при фиксированных гиперпараметрах \(\alpha\) и \(\beta\) записывается так: \[ p(w, z, \theta, \varphi \mid \alpha, \beta) = \left[\prod_{k=1}^K p(\varphi_k \mid \beta)\right] \left[\prod_{d=1}^D p(\theta_d \mid \alpha) \prod_{n=1}^{N_d} p(z_{dn} \mid \theta_d)\, p(w_{dn} \mid z_{dn}, \varphi)\right]. \] Интуитивно это означает, что мы сначала генерируем распределения слов для тем и распределения тем для документов, затем для каждого слова в документе выбираем тему из распределения \(\theta_d\) и слово из распределения \(\varphi_{z_{dn}}\). Обучение LDA заключается в приближенном восстановлении этих скрытых распределений по наблюдаемым частотам слов в матрице «документ–терм» (в нашем случае dtm_lda).

Упражнение 15 — От DFM/DTM к эмбеддингам

Классические подходы в тематическом моделировании и анализе текстов опираются на разреженные матрицы DFM/DTM, где каждый признак — отдельное слово или лемма, а значения — частоты. Такой подход хорошо работает для простых моделей, но с ростом размеров словаря и сложности задач его все чаще заменяют векторными представлениями (эмбеддингами) — плотными векторами фиксированной размерности, обученными так, чтобы отражать смысловую близость слов и текстов.

Это упражнение лучше выполнять на компьютере, так как оно требует установки модели paraphrase-multilingual-MiniLM-L12-v2- легкой мультиязычной модели, предназначенной для парафразирования и семантического анализа.

# Этот блок — демонстрация: показывает, как можно
# получить эмбеддинги для нескольких документов корпуса
# и найти самые семантически близкие тексты.

library(reticulate)

st <- import("sentence_transformers")       
util <- import("sentence_transformers.util")

model <- st$SentenceTransformer("paraphrase-multilingual-MiniLM-L12-v2")

sample_texts <- c(
  "Банк России понизил ключевую ставку и ожидает замедления инфляции.",
  "Команда выиграла чемпионат, забив гол в компенсированное время.",
  "Центральный банк обсудил меры по поддержке кредитования малого бизнеса."
)

emb <- model$encode(sample_texts, convert_to_tensor = TRUE)
# cos_sim между первым текстом и всеми
cos_scores <- util$cos_sim(emb[0], emb)  
cos_scores

Что здесь происходит:

  1. Берем 3 текста.
  2. Загружаем готовую модель SentenceTransformer, которая сопоставляет каждому тексту вектор в многомерном пространстве.
  3. Кодируем тексты в эмбеддинги и считаем косинусную близость между выбранной новостью и всеми остальными.
  4. Видим, что к новости про ключевую ставку модель находит более похожей новость про банк, кредитование (косинусная мера 0,3), даже если совпадений по конкретным словам немного: модель опирается на смысл, а не только на частоты лемм.

Сентимент-анализ

Словарный подход

Сентимент-анализ (анализ тональности) определяет эмоциональную окраску текста. Простейший подход — словарный: создается список позитивных и негативных слов, затем подсчитывается их встречаемость в каждом документе.

Предположим, у нас уже подготовлены:

  • sent_dict — словарь с ключами positive и negative (на основе пакета rulexicon и словаря hash_sentiment_nrc_emolex_ru);
  • dfm_sent — DFM на леммах (dfm_lemma);
  • sent_df — датафрейм с числом позитивных/негативных лемм и итоговым sentiment = positive - negative.

Упражнение 18 — Средняя тональность по темам

Используя датафрейм sent_df, постройте график средней тональности по рубрикам Lenta:

sent_summary <- sent_df |>
  group_by(topic_true) |>
  summarise(
    positive_total = sum(positive, na.rm = TRUE),
    negative_total = sum(negative, na.rm = TRUE),
    .groups = "drop"
  ) |>
  tidyr::pivot_longer(
    cols = c(positive_total, negative_total),
    names_to = "sent_type",
    values_to = "n"
  ) |>
  mutate(
    n = ifelse(sent_type == "negative_total", -n, n),
    sent_type = recode(sent_type,
                       positive_total = "Позитивные леммы",
                       negative_total = "Негативные леммы")
  )

ggplot(sent_summary,
       aes(x = topic_true, y = n, fill = sent_type)) +
  geom_col() +
  coord_flip() +

  group_by(topic_true) |>

    positive_total = sum(positive, na.rm = TRUE),
    negative_total = sum(negative, na.rm = TRUE),
    .groups = "drop"
  ) |>
  tidyr::pivot_longer(
    cols = c(positive_total, negative_total),
    names_to = "sent_type",
    values_to = "n"
  ) |>
  mutate(
    n = ifelse(sent_type == "negative_total", -n, n),
    sent_type = recode(sent_type,

                       negative_total = "Негативные леммы")
  )
